---
name: Время жизни временного тестового сервера
description: Особенность окружения Replit при запуске одноразового PostgreSQL для нескольких проверок.
---

Если одноразовый PostgreSQL должен обслужить несколько отдельных Shell-вызовов,
запускать `postgres` через управляемую фоновую Shell-задачу и остановить её
после проверок. Не полагаться на `pg_ctl start` из обычного Shell-вызова.
Для временного кластера явно задавать `-k "$PGROOT"`: системный каталог
`/run/postgresql` в окружении может отсутствовать, и сервер тогда завершится
при создании файла блокировки Unix-сокета даже при включённом TCP.

**Why:** сервер успешно запускался и обслуживал проверку внутри вызова,
но после завершения вызова исчезал; следующая проверка получала ECONNREFUSED.
Отдельно, отсутствующий `/run/postgresql` мешает запуску кластера с сокетом по
умолчанию.

**How to apply:** только для специально созданного временного тестового
кластера; использовать фоновую задачу на loopback с отдельным портом и
Unix-сокетом внутри временного каталога, сохранить её идентификатор для остановки.
Рабочие сервисы приложения по-прежнему запускать через их существующие workflows.
